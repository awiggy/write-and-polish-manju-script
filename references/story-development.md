# 漫剧故事开发与需求澄清

## 目标

把模糊灵感逐步转化为能够安全进入大纲、分集和单集写作的故事事实。不要把填表本身当成创作，也不要在关键方向未确认时替用户决定故事。

## 1. 先审核已有材料

先提取四类信息：

- **已确认**：用户明确给出或认可的事实；
- **显式推定**：Skill 为推进讨论提出、但尚未确认的暂定方案；
- **矛盾**：无法同时成立的设定、时间线、动机或结局要求；
- **缺口**：会阻止进入当前交付层级的信息。

不要重复询问已经明确的内容。先复述用户真正提供了什么，再判断缺口。

“已确认”采用严格口径：只能记录用户明确给出、认可，或不存在其他合理解释的直接事实。类型惯例、市场常见元素、推荐爽点和 Skill 为了补全故事而生成的内容都不是已确认事实。

## 2. 区分输入成熟度

### 明确需求

满足当前交付层级的大部分硬条件，且用户给出了明确任务。

执行方式：

1. 快速审核矛盾和缺口；
2. 只说明会影响结果的问题；
3. 没有阻断项时直接执行；
4. 不把“专业流程”变成额外阻力。

### 部分明确

已有题材、主角、冲突或结局中的若干项，但缺少关键连接。

执行方式：

1. 保留用户已有方向；
2. 找出最高影响缺口；
3. 每轮询问一到三个问题；
4. 每轮更新当前故事版本；
5. 达到目标层级后停止追问。

### 模糊需求

只有题材、情绪、一个画面、一个角色标签或一句“写个复仇故事”。

执行方式：

1. 不直接写正式剧本；
2. 先帮助用户确定方向、主角、核心冲突和结局类型；
3. 用少量选项降低表达负担；
4. 不把选项伪装成唯一答案；
5. 只有用户明确要求样片时，才输出方向测试稿。

## 3. 按影响顺序逐轮推进

### 第一层：项目方向

优先确认：

- 面向男频、女频还是泛人群；
- 主类型和主情绪；
- 现代、古代、未来还是幻想世界；
- 用户要长线连载、短篇、单集样片还是已有稿件审核。

不要一开始询问所有角色姓名。

当输入只有“复仇”“甜宠”“末世”等一个题材词时，首轮就停留在这一层。选项应保持在“受众—世界类型—交付目标”的粒度，不要用具体人物遭遇或流行套路一次绑定主角、时代、背景和叙事机制。

首轮的每道题只解决一个维度。例如：受众选“女频 / 男频 / 泛人群”，世界类型选“现代现实 / 古代历史 / 幻想未来”，交付目标选“故事大纲 / 连载方案 / 方向样片”。主情绪、主角遭遇和复仇方式放到后续对应层级，不与受众选项捆绑。

### 第二层：核心故事

优先确认：

- 主角被夺走、缺失或迫切想得到什么；
- 主角当前可执行的主动目标；
- 主要对手或核心阻碍；
- 双方目标为什么不能同时实现；
- 失败会造成什么具体损失；
- 观众主要获得什么情绪。

复仇题材还要确认：复仇原因、直接仇人、隐藏责任者、主角希望对方受到的最终结果，以及复仇是否会改变主角本人。

### 第三层：世界与权力

只建立支撑冲突所需的规则：

- 谁拥有权力，权力来自哪里；
- 主角和对手分别拥有什么资源；
- 法律、家族、宗门、公司、系统或副本如何限制行动；
- 哪些能力、证据和资源不能随意使用；
- 违反规则会付出什么代价。

现代现实题材不需要百科式世界观，但公司、家庭、法律和社会关系要能解释人物行动。幻想题材需要可验算的世界规则、能力边界和代价。

### 第四层：功能型角色与关系

先确定故事功能，再决定数量和姓名：

- 主角；
- 直接对手；
- 隐藏操盘者；
- 盟友或利益合作者；
- 可能背叛者；
- 情感关系对象；
- 掌握关键证据或规则的人。

合并功能重复的角色。每个主要角色至少拥有自己的目标、资源、底线、秘密和关系变化空间。

### 第五层：终局与主线结构

长线大纲前至少确认结局类型或终局选择：

- 主角成功并保有自我；
- 主角成功但付出不可逆代价；
- 仇人受到法律、权力、关系或生命层面的惩罚；
- 主角放弃复仇并选择更重要目标；
- 真相推翻原始复仇对象；
- 双方同归于尽或悲剧收束。

再确定：触发事件、第一次主动行动、阶段胜利、严重反击、中点真相、最低谷、最终选择和结局。

### 第六层：连载与生产

确认：

- 连载引擎如何持续产生新目标、阻碍和代价；
- 预计集数与阶段划分；
- 单集时长；
- 平台与画幅；
- 生产形态和成本限制；
- 是否需要分镜、声音和提示词。

生产参数不能替代故事准备度。

## 4. 提问协议

- 每轮只问一到三个相互关联的问题；
- 从会改变故事方向的问题开始；
- 问题过于抽象时提供二到三个互斥选项；
- 把推荐项放在第一位，并说明影响；
- 允许用户自由回答，不强迫从选项中选择；
- 用户回答后先更新故事版本，再进入下一轮；
- 用户明确说“不确定”时，提出暂定方案并标注为推定；
- 用户明确把决定权交给 Skill 时，可以提出完整推荐方案，但先标注为待确认版本或方向测试，不直接登记为正史；
- 用户改变方向时，说明会影响哪些已确认内容。

不要：

- 一次发送十几个问题；
- 只问姓名、年龄和外貌，却不问目标与冲突；
- 因为用户回答简短就替他完成所有高影响决策；
- 未经确认把测试稿中的设定写入正史；
- 为了尽快写第一集跳过结局方向和连载引擎。
- 用“你不选我就按推荐直接写”替代需求澄清和版本确认。

## 5. 每轮同步格式

单题材词示例：用户只说“帮我写一个复仇的剧本”时，“当前已确认”只能包含“题材方向：复仇”。不能添加“主角主动布局”“高智复仇”“身份反转”“仇人最终死亡”等未由用户表达的内容。

```markdown
## 当前已确认

- 

## 显式推定

- 暂定：
- 原因：

## 尚未确定

- 

## 当前就绪状态

- 可进入：方向测试稿 / 故事大纲 / 分集规划 / 正式单集 / 生产稿
- 尚不可进入：
- 阻断原因：

## 下一步只需要决定

1.
2.
```

没有推定时省略“显式推定”。没有阻断项时直接进入用户要求的交付层级，不继续追问。

## 6. 分层就绪标准

### 方向测试稿

至少有：题材或情绪、一个主角方向、一个核心冲突方向。必须标注全部高影响假设，且不得自动成为正史。

### 故事大纲

至少有：受众、题材、世界类型、主角、主动目标、主要对手、核心冲突、失败代价、结局类型、连载引擎。

### 分集规划

在故事大纲基础上增加：阶段目标、关键转折、每阶段对手策略、信息揭示顺序、预计集数和阶段结尾。

### 正式单集

在分集规划或已知上下文基础上增加：本集功能、开场状态、唯一核心事件、出场角色目标、信息边界、结束变化和锁定内容。

### 生产稿

正式单集已确认，并补齐生产形态、画幅、时长、角色与场景资产、声音和成本限制。

## 7. 故事圣经 V0.1

达到故事大纲条件后，整理：

- 项目定位；
- 一句话故事；
- 故事承诺与主情绪；
- 世界背景和权力规则；
- 主角、对手与主要功能角色；
- 人物关系；
- 核心冲突和失败代价；
- 长线连载引擎；
- 关键转折；
- 信息与秘密；
- 结局方向；
- 预计集数和生产边界；
- 已确认、推定和尚未确定的内容。

故事圣经 V0.1 是待确认事实源，不是最终剧本。用户确认后再把对应项目标记为锁定或可调整。
